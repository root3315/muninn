# Muninn: как работает код

Шпаргалка для презентации. Сначала суть в одном абзаце, потом путь одного клика от начала до
конца, потом карта файлов, формулы, цифры и ответы на вопросы жюри.

## Суть за 20 секунд

SPHEREx снимает всё небо примерно дважды в год, поэтому почти у каждой точки есть кадры на
несколько дат. Muninn берёт эти кадры прямо из архива NASA, приводит их к одной сетке и даёт
сравнить: промигать, наложить, вычесть, сложить. Звёзды стоят на месте, а то, что движется,
становится видно. Щелчок по точке измеряет её во всех заходах и говорит, что там: звезда,
вспышка, движущееся тело или ничего.

Всё считается в браузере. Сервер только раздаёт страницу и пересылает один запрос к каталогу
кадров. Сборки нет, зависимостей нет, фреймворка нет.

## Схема

```
Браузер (public/)                                  Внешние сервисы
┌───────────────────────────────┐
│ gate.js    карта неба, вход   │
│ app.js     состояние, связка  │── api/search ──▶ server.js ──▶ IRSA SIA (список кадров)
│ catalog.js запросы            │── имя объекта ─▶ CDS Sesame / SIMBAD
│ stamp.js   чтение кадра  ─────│── Range-запросы ▶ AWS S3 nasa-irsa-spherex (пиксели)
│   fits.js  разбор FITS        │── астероиды ───▶ SkyBoT (IMCCE)
│   wcs.js   координаты         │── что за звезда ▶ VizieR (Gaia DR3, AllWISE, 2MASS, VSX)
│ render.js  яркость → цвет     │
│ sky.js     холст, измерения   │
│ sectors.js / hunt.js / depth.js / stack.js   анализ
│ strip.js   нижняя лента       │
└───────────────────────────────┘
```

Зачем вообще сервер: каталог кадров IRSA не отдаёт CORS-заголовки, браузер к нему обратиться не
может. Зеркало с пикселями на AWS их отдаёт, поэтому пиксели идут в браузер напрямую и через
сервер не проходят.

## Путь одного клика

Пользователь нажал «(152) Atala» на карте неба. Дальше по шагам.

1. **Вход (`app.js: enterFrom`, `gate.js: fly`).** Камера летит к точке. Загрузка стартует
   одновременно с полётом, чтобы ожидание архива пришлось на время перелёта.
2. **Список кадров (`catalog.js: searchFrames`).** Для десяти готовых полей список лежит прямо в
   `public/data/fields/*.json` и открывается сразу. Для любой другой точки идёт запрос
   `api/search` на сервер, тот спрашивает IRSA и кэширует ответ на 12 часов.
3. **Выбор заходов (`app.js: openField`).** Кадры группируются в заходы по выбранной полосе, из
   них берётся до десяти так, чтобы покрыть весь промежуток времени, а не первые десять подряд.
4. **Чтение кадра (`stamp.js: loadStamp`).** Файл весит около 70 МБ, но читается кусками через
   HTTP Range:
   - первые 64 КБ: заголовок FITS (`fits.js`) и из него WCS, то есть привязка пикселей к небу;
   - по WCS считается, на какие строки детектора попадает поле, и запрашиваются только они
     (1–3 МБ);
   - одновременно запрашиваются те же строки плоскости `FLAGS`.
   Одновременно читаются четыре кадра, пересчёт идёт в Web Worker (`stamp-worker.js`), чтобы
   интерфейс не подвисал.
5. **Маска флагов (`stamp.js: maskFlagged`).** Пиксели, которые сам конвейер SPHEREx пометил как
   плохие (космическая частица, битый или горячий пиксель, потеря данных), обнуляются до любых
   измерений.
6. **Общая сетка (`wcs.js: TangentGrid`, цикл в `loadStamp`).** Аппарат между заходами
   поворачивается, иногда на 180°. Поэтому каждый кадр пересчитывается на одну касательную
   плоскость с севером вверх: для каждой точки сетки вычисляется, какой пиксель детектора на неё
   смотрит (TAN + дисторсия SIP), значение берётся билинейной интерполяцией. Сетка режется
   примерно на 2,5 отсчёта на пиксель детектора: мельче нет смысла, информации там нет.
7. **Яркость в цвет (`render.js`).** Чёрная точка ставится на «медиана фона + 1σ», белая на
   выбранный перцентиль, между ними кривая asinh (или log, корень, линейная). Палитры берутся из
   CSS-токенов.
8. **Показ (`sky.js: SkyView`).** Холст рисует текущий заход и разметку поверх: сетку, компас,
   кольца известных астероидов, метки. Режимы: мигание, шторка, разность A−B, один заход, стек.
9. **Секторы (`sectors.js`).** Кадр делится на 5×4 сектора. Для каждого сектора в каждом заходе
   считается, насколько он не похож на себя обычного. Результат рисуется под кадрами в нижней
   ленте (`strip.js`).
10. **Известные тела (`catalog.js: skybotCone`).** Для момента каждой экспозиции SkyBoT
    возвращает астероиды и кометы в поле. Так точка на кадре получает имя.
11. **Hunter X (`hunt.js`).** Самые заметные места (до двенадцати) измеряются во всех заходах.
    То, что движется, ранжируется по медленности и получает оценку «не дальше чем N а.е.».
12. **Глубина (`depth.js`).** По шуму настоящих пикселей детектора считается предел 5σ и
    показывается рядом с предсказанной яркостью Планеты X.

| `tools/` | скрипты проверок: поиск поля с астероидом, фотометрия, чувствительность | чем проверяли заявленное |

## Формулы и правила, которые стоит уметь объяснить

**Сектор необычен, если**

```
оценка = (пик в этом заходе − медиана пиков по заходам) / шум
```

Постоянная звезда даёт ноль, потому что она есть в медиане. Шум берётся как большее из разброса
пиков сектора и шума пикселей кадра, иначе пустой сектор делится почти на ноль. Сектор считается
выделившимся от 4.

**Измерение точки (`sky.js: measure`).** Фон и шум берутся из кольца вокруг точки, внутри ищется
пик, затем центр по весу потока. Обнаружение: пик выше фона на 5σ, где σ не меньше шума пикселей
детектора этого захода. Блеск: сумма за вычетом фона в апертуре 3×3 пикселя детектора, в
величинах AB (та же шкала, что у предела глубины). Проверено на реальном поле: постоянная
звезда 12-й величины держится в пределах 0,3 зв. вел. за десять заходов.

**Вердикт (`sky.js: trackMark`).**

| Что видно | Вердикт |
|---|---|
| ни одного обнаружения | ничего выше шума |
| одно | было один раз, дата |
| три и больше, сдвиг больше 6,15″ и больше двух разбросов | движется, скорость в ″/ч |
| во всех заходах, сдвига нет | стоит на месте |
| не во всех, сдвига нет | то есть, то нет |

**Скорость → расстояние (`hunt.js`).** Почти всё видимое движение далёкого тела даёт движение
Земли (параллакс). В противостоянии

```
скорость ≈ 2π · 206265 / (d + √d)   ″ в год,  d в а.е.
```

SPHEREx смотрит под 90° к Солнцу, там остаётся собственное движение тела `2π / d^1,5`. Из двух
расстояний берётся большее, поэтому в интерфейсе написано «не дальше чем».

Три защиты от ложного кандидата: скорость должна отличаться от нуля; нужно минимум четыре точки;
сдвиг должен превысить три пикселя детектора (18,45″).

**Глубина (`depth.js`).** Шум неба в МЯн/ср умножается на телесный угол пикселя 6,15″,
суммируется по апертуре 3×3, берётся 5σ и переводится в звёздную величину AB. Получается 17,60 AB
на один заход.

**Стек (`stack.js`).** Заходы одного сезона (до шести, в пределах 20 дней, одна полоса)
приводятся к одному уровню фона и складываются по пикселям: из трёх берётся среднее по
величине, из четырёх и больше отбрасывается самое яркое. Так уходит космическая частица или
пролетевший астероид.

## Что проверяла комиссия и что исправлено

Четыре независимых судьи (наука, код, UX, соответствие заданию) прошли проект 12 ноября 2026.

| Критерий | До правок | После (второй круг) |
|---|---|---|
| Научная достоверность | 3 | 3,5 |
| Техническое исполнение | 3,5 | 4 |
| UX и интерфейс | 3,5 | 4 |
| Соответствие заданию | 4 | 4 |
| Креативность | 4 | 4 |
| Влияние | 3 | 3,5 |
| Презентация | 2 | 3,5 |

Второй круг проверял каждое исправление по коду и нашёл дефекты в самих правках: величина
занижалась на полях 6′ и 9′, дыра в апертуре молча уменьшала блеск, медленный ответ сервера шёл
без заголовков безопасности, у презентации были ошибки при сбое сети. Они исправлены уже после
выставления этих оценок; третьего круга не было.

После этих оценок сделано: спектр отмеченной точки по шести полосам с настоящей длиной
волны пикселя, наложение положений Gaia DR3 и AllWISE на кадр, выгрузка измерений метки в
CSV, карточка с настоящим кадром на экране неба, новая презентация.

Что всё ещё держит оценки: нет снимков WISE рядом с кадром (только положения из каталога),
нет связи сезонов и сложения вдоль пробного движения (креативность, наука), нет видео на
30 секунд (презентация).

Исправлено после проверки:

- **Порог 5σ был мягче заявленного.** Шум брался с пересчитанной сетки, которая сглажена
  интерполяцией, и примерно один пустой клик из восьми давал «обнаружение». Теперь шум не меньше
  шума пикселей детектора.
- **Яркость точки мерялась пиковым пикселем**, у постоянной звезды он гулял до двух раз. Теперь
  это апертура 3×3 пикселя в величинах AB.
- **Флаги конвейера применялись молча.** Теперь в подписи кадра написано, сколько пикселей
  замаскировано.
- **Презентации не было.** Теперь она на сайте: `talk.html`, ссылка с главного экрана.
- **Порог «движется» считался по сетке (2,46″), а не по пикселю детектора (6,15″).** Около 6 %
  неподвижных звёзд получали «движется». Исправлено, разброс считается с учётом степеней свободы.
- **Стек выбрасывал заход с самым ярким фоном вместо космической частицы.** Теперь фон каждого
  захода выравнивается перед сложением.
- **Оценка расстояния не учитывала геометрию 90°.** Тело на 2,2 а.е. получало «не дальше 1,9».
  Теперь берётся большее из двух расстояний.
- **Сервер падал от одного кривого запроса** (`GET //`). Исправлено, добавлен тест.
- **Заголовки безопасности (CSP) не отдавались** сервером на ТВ-боксе. Теперь сервер читает их из
  того же файла, что и Cloudflare.
- **Сбой сети выдавался за «SPHEREx сюда не заходил».** Теперь это отдельное сообщение с кнопкой
  повтора. На все запросы поставлен таймаут.
- **Неиспользуемый пересыльщик `/api/fits` удалён.**
- **Интерфейс:** ошибка поиска показывается на экране неба рядом с полем ввода; язык и справка
  доступны с первого экрана; лого ведёт на небо; подпись при наведении больше не наезжает на имя
  объекта; у 48 объектов Мессье убрана ложная величина «0,0 mag»; тексты укорочены; удалено
  200 строк мёртвого CSS.
- **Телефон:** снимок на всю ширину, стрелки с датами под ним, шапка в две короткие строки,
  режимы в одну строку.
- **Скорость:** сжатие brotli/gzip (код страницы 700 КБ → около 180 КБ, список кадров 390 → 35 КБ),
  проверка по ETag, предзагрузка модулей, фото Луны грузится после старта, кадр и его флаги
  читаются одновременно.

## Что не сделано, говорить прямо

- Блеск не приводится к одной длине волны: внутри полосы она от захода к заходу разная. Поправки
  на свет за пределами апертуры нет.
- Спектра отмеченного источника по шести полосам нет.
- Панели с изображениями WISE и Gaia нет: есть только опознание отмеченной точки по каталогам.
- Медленное тело не связывается между сезонами: на 500 а.е. оно прыгает на 13,6′, а окно
  измерения ±12″.
- Утверждение «тело на 500 а.е. в стеке остаётся в пределах двух пикселей» верно у эклиптики. На
  широте 20° это около четырёх пикселей за 11 дней, у полюсов около тринадцати.
- WISE 0855 в одном заходе, скорее всего, не виден: около 17,2 AB при пределе 16,7 в D6.
- Видео на 30 секунд нет. Слайды есть: `talk.html`.
- Проект начат до выходных хакатона 14–15 ноября. Проверить правила допуска до подачи.
- У предсказания «V 22–25» для Планеты X в репозитории нет ссылки на источник. Найти статью и
  вписать её в README и на слайд 6 до подачи.
- Звезда Барнарда за 212 дней проходит 6,0″, чуть меньше пикселя 6,15″: метка на ней честно
  говорит «неподвижно».

## Выступление

Презентация встроена в сайт: ссылка «Презентация, 7 слайдов» в правом верхнем углу экрана неба,
адрес `/talk.html`. Листать: стрелки, пробел или шкала внизу. На первом слайде четыре настоящих
кадра читаются из архива вживую; клик по дате останавливает мигание на этом заходе (на 25 декабря
виден астероид в кольце), клик по снимку запускает снова. Язык переключается кнопкой.

**Слайды**

1. Muninn показывает, что изменилось между заходами SPHEREx. На экране: мигание поля Atala.
2. Файлы по 70 МБ читаются по 1–3 МБ прямо в браузере. На экране: строка «прочитано N МБ из M».
3. Инструмент находит и называет движущееся тело. На экране: кадр 25 декабря, кольцо SkyBoT.
4. Инструмент отказывается от ложного открытия. На экране: 6 июля, `FLAGS 0x80005`.
5. Все пять целей задания открываются одним нажатием. На экране: строка «Цели задания».
6. SPHEREx не дотягивает до Планеты X на 1,5–4,5 величины. На экране: панель «Глубина поиска».

## Вопросы жюри

**Вы нашли Планету X?** Нет. SPHEREx слишком неглубок: даже 200 сложенных заходов не дотягивают
на 1,5–4,5 величины. Мы это измерили по настоящим пикселям.

**Как понять, что обнаружение настоящее?** Порог 5σ по шуму детектора, маска флагов конвейера,
сверка со SkyBoT на момент экспозиции, для скорости минимум четыре точки.

**Какая доля ложных срабатываний?** До правки около 1,3 % на заход, то есть примерно один пустой
клик из восьми. После привязки шума к детектору порядок падает до 10⁻⁵ на заход для гауссова
шума. На реальных кадрах после правки не перемеряли.

**Изменение яркости RW Aur настоящее?** Блеск меряется апертурой 3×3 пикселя, постоянная звезда
держится в пределах 0,3 величины. Но длина волны внутри полосы от захода к заходу разная, поэтому
изменение в несколько десятых мы не докажем. Большую амплитуду Миры видно.

**Где WISE и Gaia?** Опознание отмеченной точки по каталогам через VizieR. Панели с
изображениями нет.

**Может ли Hunter X найти далёкое тело?** В нынешнем виде почти нет: окно ±12″, глубина одного
захода 17,6. Это честная машина нулевого результата, а не детектор.

**Что будет, когда выйдет новый выпуск данных?** Имя коллекции добавляется в
`public/js/release.js`, затем `npm run bake` и деплой. Пиксели страница не хранит.
